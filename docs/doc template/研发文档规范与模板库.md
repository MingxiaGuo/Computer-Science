# 二、通用文档规范

## 2.1 文档基本信息

所有正式文档建议统一使用以下信息：

| 字段   | 填写说明           |
| ---- | -------------- |
| 文档名称 | 文档标题           |
| 文档编号 | 唯一编号           |
| 文档分类 | 调研、设计、测试等      |
| 作者   | 文档编写人          |
| 评审人  | 技术或项目评审人员      |
| 创建日期 | 首次创建日期         |
| 更新时间 | 最近更新时间         |
| 文档版本 | V1.0、V1.1      |
| 文档状态 | 草稿、评审中、已发布、已废弃 |
| 适用范围 | 关联项目或系统        |

## 2.2 文档版本记录

| 版本   | 日期         | 修改人 | 修改内容     |
| ---- | ---------- | --- | -------- |
| V1.0 | YYYY-MM-DD | XXX | 初始版本     |
| V1.1 | YYYY-MM-DD | XXX | 补充技术实现方案 |

## 2.3 文档命名规范

推荐格式：

`分类-项目/模块-文档主题-V版本`

示例：

- 调研-veRL-技术调研-V1.0
- 设计-强化学习平台-系统架构设计-V1.0
- 测试-GPU调度-性能测试报告-V1.0
- 运维-Ray集群-部署手册-V1.0

# 十二、模板建设原则

1. 模板统一，但不强制每份文档填写全部章节。
2. 每个章节提供填写说明，降低使用门槛。
3. 关键设计文档必须包含架构图或流程图。
4. 调研报告必须区分事实、分析和结论。
5. 方案设计必须包含异常处理、风险和验证方式。
6. 测试报告必须有实际数据和明确结论。
7. 正式发布的文档必须保留版本及修订记录。
8. 避免重复建设：技术调研、技术分享、源码分析应明确各自定位。

**最终目标：** 建立一套覆盖调研、设计、开发、测试、部署、运维、复盘全过程的研发文档标准体系，让研发文档具备统一结构、可复用模板和可持续维护能力。

建议下一步： 不只是把模板放进知识库，还可以建立每种文档的「填写示例 + 优秀案例 + 空白模板」三件套，让团队成员拿来就能用。

后续也可以每月整理一次团队新出现的文档类型，补充和优化模板库。
